# Expand/contract

Frappe has no down migration: rollback is restoring the pre-migrate backup. Keep each release valid for both the previous and next code.

1. **Expand,** release N. Add the new field/DocType alongside the old one. Write both from the server, but keep reading the old one: it stays authoritative while previous-release workers, or a code-only rollback, can still write only the old shape.
2. **Migrate,** release N+1, after every deployed site runs N and no pre-N writer can run. A registered, idempotent, batched patch backfills the new shape from the old, catching rows that only old code wrote. Add its legacy rows to the lifecycle fixtures and test results as business data (amounts, precision, provenance), not only row counts.
3. **Switch,** in the same release N+1. Read only the new shape; keep writing both, because release-N workers or a rollback to N still read the old one.
4. **Contract,** in a later release after every deployed site ran step 2 and no release that reads or writes the old shape can still run (release N+1 still writes it, so it too must be drained and no longer a rollback target), stop writing it and remove it:
   - **Column-backed field:** delete it from the DocType JSON. Frappe leaves the database column in place; `bench trim-tables` drops orphan columns. Complete the non-column and attachment cleanup below before removing the field metadata or trimming.
   - **Single value or child-table field:** `trim-tables` skips Singles and cannot remove `Table`/`Table MultiSelect` rows. Before removing metadata, use a registered, idempotent `[pre_model_sync]` contraction patch to migrate the retained values/children to their replacement, or delete only data explicitly retired by the contraction plan. Scope Single cleanup by `tabSingles.doctype` and `field`; scope child cleanup by both `parenttype` and `parentfield`, plus `parent` when contracting only selected documents. Preserve children belonging to other parents that reuse the child DocType. Lifecycle fixtures must assert the old state is gone, retained business values survive, unrelated rows are untouched, reruns are safe, and reusing the old fieldname cannot resurrect retired values or children.
   - **Attach or Attach Image field:** before removing metadata or trimming its column, a registered, idempotent `[pre_model_sync]` contraction patch must rehome, detach, or delete the associated `File` rows according to the retention plan. Scope by `attached_to_doctype`, `attached_to_field`, and affected document names; update the complete attachment relationship through Frappe's File APIs while preserving private storage and permission scope. Clear stale attachment references when detaching, and delete files only when the plan explicitly retires them. Leaving `File.attached_to_field` on the removed field makes later private/public URL propagation write a nonexistent field. Cover a private attachment, an unaffected attachment, safe reruns, and a controlled private/public transition on a temporary-site fixture after contraction and approved trimming; assert it succeeds without writing the removed field and restores the intended privacy state.
   - **DocType:** first move or delete what still references it (`Link` and `Table` fields, User Permissions, DocShares, attached Files, reports, workspace entries, DocType registries and other `hooks.py` entries), then delete its module folder. `bench migrate` removes the orphan `DocType` record but keeps the table; `bench trim-database` drops it.
   - Both trim commands are destructive and site-wide (`trim-database` drops every deleted DocType's table, other apps' included). Run each with `--dry-run` per site, show the user the list, and run it for real only with their explicit approval, never on the persistent dev or test site as part of a routine gate.

Done when each release passes the lifecycle sequence and no code reads or writes the old shape.
