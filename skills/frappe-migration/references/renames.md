# Renames

The two renames run on opposite sides of model sync, each in a patch whose rerun is a no-op:

- **DocType:** `frappe.rename_doc("DocType", old, new, force=True)` in a `[pre_model_sync]` patch, so the table and links move before the renamed JSON syncs. `rename_doc` loads the old DocType first and raises when it is gone, so guard on existence: rename when only the old exists, skip when only the new exists, and throw when both or neither exist. Test a forced rerun. `DocType.after_rename` skips renaming files and folders while `frappe.flags.in_patch` is set, so rename the module folder, JSON, controller, test files, and controller class in the repository in the same change.
- **Field:** `frappe.model.utils.rename_field.rename_field(doctype, old, new)` in a `[post_model_sync]` patch. It requires the synced DocType and silently returns when the new field is missing, so a pre-sync call copies nothing. It copies every row into the new column with an unconditional `UPDATE`, and Frappe leaves the old column in place, so a forced rerun (for example a lifecycle harness that deletes Patch Logs to requeue patches) overwrites values the app has since written with stale legacy ones. Patch Log is not a guard: skip the call when a durable marker says the copy already ran, for example a namespaced `frappe.db.set_global` key that cannot match a fieldname, set in the same patch after the copy. Test that a forced rerun after editing the new field on a migrated row keeps the edit. A renamed `unique` field hits the same sync failure as an additive one (see [staged-constraints.md](staged-constraints.md)): stage it the same way. For a `Table` or `Table MultiSelect` field, do not call `rename_field`: the parent table has no column, so default validation returns early, and with `validate=False` it updates `parentfield` without a `parenttype` predicate, moving the children of every parent that reuses the child DocType. Update the child table where `parenttype` is this DocType and `parentfield` is the old name (a rerun matches nothing), call `update_property_setters` from the same module if any exist, and test that the children load under the new field while another parent's children stay attached. For an `Attach` or `Attach Image` field, `rename_field` leaves `File.attached_to_field` on the old name, and a later private/public change writes the new URL through that stale name; in the same patch update `File` rows for this DocType from the old fieldname to the new one (idempotent by its `WHERE`) and test a private attachment.

Field renames must also migrate database-resident references that repository searches cannot see. Inventory site customizations in `Custom Field`, `Property Setter`, and stored `DocField` metadata, including Dynamic Link `options`, `fetch_from` paths, and dependency expressions (`depends_on`, `mandatory_depends_on`, `read_only_depends_on`). `rename_field` updates some reports, settings, and property-setter targets, but does not rewrite these field references. Use a registered, idempotent patch to rewrite references that resolve to the renamed field, including references from other DocTypes; preserve unrelated fields with the same name. Inspect expression semantics rather than globally replacing text, and stop with an actionable error for ambiguous references. Clear affected metadata caches. Seed populated customization fixtures and verify that dynamic links, fetched values, and dependencies resolve through the new name, unrelated customizations remain unchanged, and a forced rerun preserves the result.

Verify the migrated business data on representative legacy rows, not just the absence of errors. Then update every reference in the same change: controllers, shared utilities, `hooks.py` (DocType registries, permission hooks, `doc_events`), whitelisted API projections, reports, Desk JS, any SPA, tests, factories, seed data, and the app's data-model docs; the app's own migration notes may list more. Done when no active database customization still resolves to the old field, `git grep` for the old name returns only the patch and its lifecycle fixtures and assertions, and `git ls-files` lists no path containing its snake_case form.
